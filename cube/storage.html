1为什么需要 Volume

CubeSandbox 运行在轻量级 MicroVM 内，默认情况下沙箱内写入的所有数据都是临时的，沙箱销毁后即消失。Volume（持久卷） 为沙箱提供与生命周期解耦的持久化存储：创建一个 Volume → 挂载到沙箱内读写 → 沙箱销毁后数据保留 → 下次再挂载到新沙箱继续使用。

CubeSandbox 的 Volume 体系兼容 E2B Volume 协议，同时通过可插拔的 Volume Plugin 架构支持接入对象存储（S3 / 腾讯云 COS）、分布式 POSIX 文件系统（JuiceFS）、共享文件存储（NFS）等任意后端。

版本要求：
• 基础 Volume 能力（创建、查询、删除、挂载、只读挂载、多沙箱共享）要求 Cube 平台 ≥ 0.6.0（CubeAPI、CubeMaster、Cubelet 均需升级），使用 Python SDK 时要求 cubesandbox ≥ 0.6.0。
• 通过 private_data 动态绑定桶与凭证（POST /v2/volumes）要求 CubeAPI、所有 CubeMaster、Cubelet ≥ 0.8.0、所选插件支持该协议，以及 Python / Go / Node SDK ≥ 0.8.0。该接口不会自动回退到 POST /volumes。
核心设计特点说明
生命周期解耦Volume 由管理面独立创建与销毁；沙箱销毁时仅卸载挂载点，后端持久化数据完整保留。
凭证不进沙箱对象存储密钥、元数据库密码等凭证只保存在宿主机节点（CubeMaster / Cubelet），沙箱内部只看到标准目录。
引用计数自动管挂载同一节点上多个沙箱挂载同一个 Volume 时，Cubelet 只在首个沙箱创建时挂载一次（0→1），后续沙箱复用已有挂载；直到该节点最后一个沙箱销毁（1→0）才卸载。
安全删除保护CubeMaster 在 t_cube_volume 维护集群级引用计数；只要仍有节点持有挂载（refcount ≠ 0），DELETE /volumes/{id} 会返回 409，防止误删使用中的数据。
单沙箱读写 / 只读隔离读写与只读是每次挂载的属性而非卷的全局属性。同一个 Volume 可以同时以读写方式挂给写入沙箱，以只读方式挂给多个只读沙箱。
兼容跨机恢复Volume 数据存放在共享后端，与 VM Snapshot 后端解耦；使用支持跨机的快照（jfs / s3）时，沙箱可在其他配置了相同驱动的节点上恢复并自动重新挂载。
一句话：Volume 把「存储生命周期」从「沙箱生命周期」里抽出来——沙箱可以随时销毁，数据留在共享后端，下次换个沙箱再挂上。

数据面挂载链与 Mount Namespace

理解「插件返回的 hostPath 如何进入 MicroVM」是写好 Node Hook 的关键。Cubelet 内部执行链如下（源码见 Cubelet/storage/pluginvolume.go）：

→
per-sandbox bindMS_BIND | MS_REC
→
virtiofs 共享目录/data/cubelet/hostdir/<sandboxID>/<rw|ro>/<volumeName>
→
MicroVM 内路径/workspace
  1. 元数据注入：沙箱创建时，CubeAPI 将请求中的 volumeMounts 透传给 CubeMaster；CubeMaster 查 t_cube_volume 补齐 driver 与 private_data，以 plugin-volume-mounts 和 plugin-volume-sources 注解随创建请求下发给目标 Cubelet。
  2. 驱动路由与串行化：Cubelet 的 volume.Manager 按 driver 名路由到对应插件，并使用按 volumeID 粒度的互斥锁（volMu）串行化同一卷的并发 Attach / Detach，避免两个并发请求同时看到 refCount == 0 造成重复挂载或挂载 / 卸载交错。
  3. 路径安全校验：插件返回 hostPath 后，Cubelet 通过 validateHostPathUnderBase 强制校验 hostPath 必须是绝对路径且严格位于 volume_plugin_base_dir（默认 /data/cube-shared/volume）的子路径内；若越界，Cubelet 立即调用 Detach 回滚并让沙箱创建失败。
  4. Per-Sandbox Bind Mount → virtiofs：Cubelet 将共享的 hostPath 以 MS_BIND | MS_REC 绑定挂载到当前沙箱专属的 virtiofs 共享目录 /data/cubelet/hostdir/<sandboxID>/<rw|ro>/<volumeName>。如果本次沙箱声明了 readOnly: true，Cubelet 再执行一次 MS_BIND | MS_REMOUNT | MS_RDONLY 只读重挂——因此插件本身不需要关心单沙箱的只读标志。
  5. 销毁清理：沙箱销毁时，Cubelet 先调用插件 Detach（由 refCount == 0 决定是否卸载共享后端），再执行 umount(MNT_DETACH) 清理该沙箱专属的 bind-mount。
Mount Namespace 机制：Cubelet 启动时通过 unshare(CLONE_NEWNS) 运行在独立的 mount namespace 中。
• 插件在 Attach 阶段建立的挂载（FUSE、NFS、bind-mount 等）必须对 Cubelet 的 mount namespace 可见；宿主机根 mntns 的 /proc/mounts 通常看不到这些挂载。
• binary 插件由 Cubelet 直接 fork/exec 启动，自动继承 Cubelet 的 mount namespace，无需额外处理。
• rpc 插件作为独立常驻进程运行在自己的 mount namespace 中；如果 Node 侧采用 RPC 形态，必须确保其挂载在 Cubelet 的 mntns 中可见（例如通过共享挂载传播或 nsenter 进入 Cubelet mntns）。

插件形态：binary vs rpc

维度binary（推荐入门）rpc（长驻 gRPC 服务）
调用方式每次 Hook fork 子进程，命令行参数输入 + stdout 单行 JSON 输出通过 socket_path（Unix socket 或 TCP）调用 gRPC
实现语言任意语言（Go、Shell、Python、Rust 等）任意支持 gRPC 的语言
Mount Namespace由 Cubelet fork，自动继承 Cubelet mntns独立进程，需自行处理与 Cubelet 的 mntns 对齐
运维复杂度无常驻进程，免进程守护需单独部署并托管守护进程（systemd / DaemonSet）
适用场景绝大多数插件（S3、JuiceFS、NFS、COS 默认均为 binary）需要复用长连接池、内存状态或超高频低延迟调用
错误表示约定：binary 插件通过非零退出码和 / 或 stdout JSON 中非空 "error" 表示失败；rpc 插件通过 gRPC error status 返回错误（protobuf 响应消息不含 error 字段）。

3两级引用计数与端到端生命周期

同一 Volume 可同时挂载到同一节点或多个节点上的多个沙箱，平台通过节点本地 + 集群级两级引用计数协调挂载与删除保护。理解 refCount 的语义，是理解整个 Volume 体系的核心。

集群级 RefCount CubeMaster t_cube_volume.refcount（最小钳位为 0） 决定 DELETE /volumes/:id 是否放行；refcount ≠ 0 返回 409

节点本地语义：

  • Attach 前先 Acquire，并将 Attach 之前的计数作为 refCount 传给插件：0 表示本节点首次挂载，需要建立后端挂载；> 0 表示已有挂载，直接返回既有 hostPath。若插件返回失败，Cubelet 自动回滚本地计数。
  • Detach 前先 Release，并将 Detach 之后的计数作为 refCount 传给插件：0 表示本节点最后一个沙箱退出，可以卸载共享后端（不得删除持久数据）；> 0 则 no-op。若插件返回失败，Cubelet 自动回滚本地计数。

集群级语义：只有当某节点本地计数发生 0 → 1 或 1 → 0 跳变时，Cubelet 才在沙箱创建 / 销毁响应的 ext_info["cube-volume-refcount-events"] 中上报事件（referenced=1 或 referenced=0；创建失败回滚不触发上报）。CubeMaster 将其累加到 t_cube_volume.refcount，当 refcount ≠ 0 时拒绝 DELETE /volumes/:id 并返回 409。

0 无挂载 → Attach 1 首次 mount → Attach 2 复用 hostPath → Detach 1 不卸载 → Detach 0 umount，保留数据
refCount 语义对照：Attach 传「挂载前」计数，Detach 传「卸载后」计数。
Hook传入的 refCount含义插件应做的动作
Attach0本节点首次挂载建立后端 mount（FUSE / NFS / bind 等）
Attach> 0本节点已有挂载直接返回既有 hostPath，不重复 mount
Detach0本节点最后一个沙箱退出umount 宿主机侧挂载，保留后端数据
Detach> 0仍有其他沙箱使用no-op

生命周期速览

阶段触发操作平台与插件行为
1. 创建卷Volume.create(...)CubeMaster 调用 Controller Create 在后端准备资源，写入 t_cube_volume。
2. 首次挂载节点上第 1 个沙箱挂载该卷Cubelet 调用 Node Attach(refCount=0) 将后端挂载到宿主机，再经 virtiofs bind-mount 进 MicroVM。
3. 共享复用同节点第 N 个沙箱挂载该卷Cubelet 调用 Node Attach(refCount>0)，直接复用已有宿主挂载，不重复 mount。
4. 沙箱销毁仍有其他沙箱使用该卷卸载当前沙箱的 bind-mount 并扣减计数，共享后端挂载保持不变。
5. 最后卸载节点上最后一个沙箱销毁Cubelet 调用 Node Detach(refCount=0) 卸载宿主侧挂载，后端数据保留。
6. 删除卷Volume.destroy(...)引用计数归零时，CubeMaster 调用 Controller Destroy 清理后端资源并删除 DB 记录。

端到端时序

① 创建 Volume（管理面）

SDK POST /volumes 或 POST /v2/volumes → CubeAPI → CubeMaster → Controller Create(volumeID, name, private_data) 返回 {token, private_data, error} → 写 t_cube_volume。

② 创建沙箱并挂载（数据面）

POST /sandboxes {volumeMounts} → CubeMaster 下发 plugin-volume-sources（含 driver、private_data）→ Cubelet 调 Attach(refCount=0, volumeBaseDir, private_data) → 校验 hostPath → bind-mount（rw/ro）→ virtiofs；回传本节点 0→1 事件，集群计数 +1。

③ 销毁沙箱（数据面）

DELETE /sandboxes/:id → Cubelet 调 Detach(refCount=0, metadata) → umount 该沙箱专属 bind-mount；回传本节点 1→0 事件，集群计数 -1。后端数据保留。

④ 删除 Volume（管理面）

DELETE /volumes/:id → CubeMaster 检查 refcount ≠ 0 则返回 409；refcount == 0 时调 Controller Destroy(volumeID, stored private_data) → 硬删除 DB 记录。

Destroy 不会自动 Detach 运行中的沙箱。删除卷前必须先销毁所有挂载该卷的沙箱，否则会收到 409。

4现有插件与选型

CubeSandbox 仓库内置了 4 套面向不同存储后端的现成 Volume 插件，覆盖对象存储、高性能 POSIX 文件系统与企业级 NFS；此外也可以按第 8～10 节自行开发插件接入内部存储系统。

默认 / 通用

选 s3

快速开箱、常规持久化、多租户对象存储。默认安装已捆绑 MinIO，零配置可用；也支持一键切换外部 S3 / COS / R2。

已有 NAS

选 nfs

已有共享 NAS / NFS 文件系统，按显式卷名按需挂载预建目录，注销卷时保留原目录数据。

自研存储

自己写插件

自定义内部存储系统，按第 8～10 节实现自己的 binary 或 rpc 插件。

5部署 Volume

5.1 默认安装（开箱即用）

如果使用 one-click 一键部署 或 Kubernetes Helm 默认值 安装 CubeSandbox，系统已经自动完成以下配置：

  1. 启动内置 MinIO 作为 S3 兼容对象存储后端（默认桶 cube-volumes）。
  2. 自动安装 cube-volume-s3 插件与 s3fs 依赖，并生成 volume-s3.conf。
  3. 在 CubeMaster 与 Cubelet 中将 s3 注册为默认驱动（volume_plugins 列表第一项）。
如果只需要使用默认 S3 持久卷，不需要手动修改任何配置，直接跳到 第 6 节。

5.2 接入外部 S3（AWS / COS / R2 / MinIO）

如需将默认 S3 插件的后端切换为外部对象存储，请按部署方式修改配置源——安装器会自动渲染 volume-s3.conf，不要手动编辑 volume-s3.conf（重新部署或升级时会被覆盖）。

one-click：.one-click.env（或 .env） 
# 关闭内置 MinIO，改接外部 S3 兼容存储
CUBE_SANDBOX_MINIO_ENABLED=0
CUBE_S3_ENDPOINT=https://s3.example.com
CUBE_S3_ACCESS_KEY_ID=<your-access-key>
CUBE_S3_SECRET_ACCESS_KEY=<your-secret-key>
CUBE_S3_BUCKET=cube-volumes
# CUBE_S3_REGION=us-east-1
# MinIO 或含点号桶名等场景开启 path-style：
# CUBE_S3_S3FS_EXTRA_OPTS=-ouse_path_request_style

多节点集群中，计算节点不部署 MinIO，直接将控制节点上的 CUBE_S3_* 同步到计算节点的 .env 后执行安装：

# 在控制节点导出 S3 配置，粘贴到各计算节点 .env
grep '^CUBE_S3_' /usr/local/services/cubetoolbox/.one-click.env
使用控制节点内置 MinIO 供多机共享时，请确保计算节点可以访问控制节点的 9000/tcp 端口。
Kubernetes Helm：values.yaml

  enabled: false

  endpoint: https://s3.example.com

5.3 部署与注册其他插件（JuiceFS / NFS / COS / 自定义）

无论部署仓库内置的其他插件还是自行开发的插件，通用步骤均分为三步：

第 1 步：安装宿主机依赖与插件程序
CubeMaster 节点部署插件二进制（或启动 RPC 守护进程）及配置 / 凭证；每个 Cubelet 计算节点部署相同程序、配置 / 凭证，并安装挂载依赖（s3fs、juicefs、mount.nfs、cosfs），确认存在 /dev/fuse（FUSE 类插件必需）。

↓
第 3 步：重启服务

name 全链路一致且唯一CubeMaster 与所有 Cubelet 注册的 name（即 driver）必须完全一致，同一进程内不能重复。

from cubesandbox import Sandbox, Volume

vol = Volume.create("my-data", driver="s3")

with Sandbox.create(volume_mounts={"/workspace": vol}) as sb:
    sb.files.write("/workspace/hello.txt", "persisted across sandboxes")
    print(sb.files.read("/workspace/hello.txt"))

# 3. 退出 with 后沙箱销毁（触发 Node Detach），但后端数据完整保留
with Sandbox.create(volume_mounts={"/workspace": vol}) as sb:
    print("re-mounted:", sb.files.read("/workspace/hello.txt"))

# 4. 彻底删除 Volume（触发 Controller Destroy；卷不存在时返回 False，幂等）

参数说明
name可选，须匹配 ^[a-zA-Z0-9_-]+$ 且最长 128 字符；省略时由服务端自动生成 UUID 作为 volume_id（注：nfs 等需要匹配预建目录的插件要求显式指定 name）。
driver可选，对应 volume_plugins[].name；省略时使用列表第一项。
volume_mounts{沙箱内绝对路径: Volume | volume_id | VolumeMount}，单次创建可同时挂载多个不同 Volume；同一沙箱内不能重复挂载同一个 Volume。
Go 
package main

import (
    "context"
    "errors"
    "fmt"

    cubesandbox "github.com/tencentcloud/CubeSandbox/sdk/go"
)

func main() {
    client := cubesandbox.NewClient(cubesandbox.NewConfigFromEnv())
    ctx := context.Background()

    // 1. 创建 Volume（Driver 省略时取 volume_plugins 第一项）
    vol, err := client.CreateVolume(ctx, cubesandbox.CreateVolumeOptions{
        Name:   "my-data",
        Driver: "s3",
    })
    if err != nil {
        panic(err)
    }

    // 2. 创建沙箱并挂载（ReadOnly: true 表示只读挂载）
    sb, err := client.Create(ctx, cubesandbox.CreateOptions{
        TemplateID: "base",
        VolumeMounts: []cubesandbox.VolumeMount{
            {Name: vol.VolumeID, Path: "/workspace"},
        },
    })
    if err != nil {
        panic(err)
    }

    // 3. 销毁沙箱（解绑 Volume）
    if err := sb.Kill(ctx); err != nil {
        panic(err)
    }

    // 4. 删除 Volume
    if err := client.DeleteVolume(ctx, vol.VolumeID); err != nil {
        switch {
        case errors.Is(err, cubesandbox.ErrVolumeInUse):
            fmt.Println("volume is still mounted by a sandbox (HTTP 409)")
        case errors.Is(err, cubesandbox.ErrVolumeNotFound):
            fmt.Println("volume already deleted")
        default:
            panic(err)
        }
    }
}

6.3 只读挂载与多沙箱共享

同一个 Volume 可以同时被多个沙箱挂载，并且每个沙箱可以独立选择读写或只读模式（只读挂载为 CubeSandbox 扩展能力，官方 E2B SDK 无此选项）：

from cubesandbox import Sandbox, Volume, VolumeMount

dataset = Volume.create("shared-dataset", driver="s3")

# 写入沙箱：默认读写
writer = Sandbox.create(volume_mounts={"/dataset": dataset})
writer.files.write("/dataset/index.txt", "v1")

# 读取沙箱：只读挂载，禁止修改但可看到 writer 的最新写入
reader = Sandbox.create(
    volume_mounts={"/dataset": VolumeMount(dataset, read_only=True)},
)
print(reader.files.read("/dataset/index.txt"))  # → v1

# 必须先销毁所有挂载该 Volume 的沙箱，再调用 Volume.destroy
writer.kill()
reader.kill()
Volume.destroy(dataset.volume_id)
只读是单次挂载的属性而非不可变快照：只读沙箱无法创建、修改或删除文件，但仍能观察到其他读写挂载产生的数据变更。

6.4 使用 private_data 动态绑定后端（Cube ≥ 0.8.0）

在多租户场景下，不同用户可能需要将 Volume 绑定到各自独立的存储桶、目录前缀与凭证，而不希望每次都修改集群配置或重启服务。Cube ≥ 0.8.0 提供 POST /v2/volumes 及对应 SDK 方法，允许在创建卷时向插件透传不透明的 private_data 字符串（最长 1024 字节）。

以内置 s3 插件为例，在各 CubeMaster / Cubelet 主机预先放置凭证引用文件 /etc/cube/s3-credentials/user-a.conf（权限 0600）后，即可按卷动态指定桶与前缀：

import json
from cubesandbox import Sandbox, Volume

vol = Volume.create_with_private_data(
    name="user-a-workspace",
    driver="s3",
    private_data=json.dumps({
        "bucket": "customer-bucket",
        "prefix": "workspaces/user-a/",
        "cred_ref": "user-a",
    }),
)

with Sandbox.create(volume_mounts={"/workspace": vol}) as sb:
    sb.files.write("/workspace/result.txt", "isolated in customer-bucket")

Volume.destroy(vol.volume_id)
安全与使用注意：
• private_data 只能携带桶名、前缀、地域和凭证引用名（如 cred_ref），绝不能传入明文 AccessKey / SecretKey。
• 动态 S3 卷所使用的桶必须预先存在（不会自动建桶），且目标前缀必须为空。

6.5 配合快照、回滚、克隆与跨机恢复

Volume 采用外部引用（external-reference）语义——快照只保存卷 ID、容器挂载路径与只读标志，不会复制 Volume 中的数据。

操作行为注意事项
FromSnap（从快照创建）可以省略 volumeMounts，平台会自动按快照记录重新挂载；也可以像 E2B 客户端一样重新传入 volumeMounts。重新传入时必须与快照记录完全一致（相同的卷、路径和只读属性），否则返回 HTTP 400。
fs-only 快照仅包含根文件系统，不记录挂载配置。从 fs-only 快照创建沙箱时，如需挂载卷必须重新声明 volumeMounts。
Rollback（回滚）恢复 VM 内存和根文件系统状态，保留当前外部 Volume 挂载。Volume 内数据保持最新状态，不会回滚到快照时刻。
Clone（克隆）克隆出的沙箱共享同一个 Volume。读写挂载的修改对源沙箱及其他克隆可见。
跨机恢复Volume 后端与 VM Snapshot 后端相互独立；VM Snapshot 使用共享后端（--backend s3 或 jfs 且 remote_status=ready）时，目标节点可自动 Attach 并恢复。目标节点必须注册了同名 Volume driver 且能访问同一后端存储。

四个 Hook 的输入 / 输出语义，是插件开发的协议契约。注意：driver 不是 Hook 入参——平台在调用 Hook 之前已按 name 选定插件。

Create（Controller）

方向字段类型说明
输入volumeIDstring稳定 ID（用户指定 name 或服务端生成的 UUID）
输入namestring展示名
输入private_datastring可选的不透明调用方输入，由 CubeMaster 原样转发（最长 1024 UTF-8 字节）。binary：--private-data，为空时不传
输出tokenstring可选鉴权令牌，返回给 SDK
输出private_datastring插件私有状态（最长 1024 字节），写入 t_cube_volume 并转发给 Attach 与 Destroy；不返回给 Volume API/SDK 客户端。可为空
输出errorstring成功时为 ""（仅 binary stdout JSON）

binary 调用示例

{"token":"","private_data":"{\"v\":1,\"bucket\":\"bucket-a\",\"prefix\":\"workspaces/a/\",\"cred_ref\":\"user-a\"}","error":""}

插件不应返回 HTTP 状态码或 CubeMaster 内部 ret_code，而是通过封闭集合字段 error_kind 声明错误类别：

{"error":"cred_ref is required","error_kind":"invalid_argument"}
error_kindCubeMaster ret_codeCubeAPI HTTP 状态说明
invalid_argument130400400仅适用于 binary Create 的调用方参数错误
缺失、未知或格式错误130593500通用插件失败
协议细节：
• 插件必须输出一个完整的 JSON 对象且 error 非空；返回类型化错误时仍应保持非零退出码（如 exit 1）以兼容旧版 CubeMaster。
• 若响应携带了 error_kind（包括空字符串或 null）但 error 为空，视为协议失败。
• 进程启动失败、被取消、超时或被信号中断时始终按执行故障处理，不解析 stdout 中的 error_kind。
• error 消息必须可安全公开展示，不得包含凭据、凭据文件路径或原始 private_data；驱动不会向类型化调用方错误追加 stderr。stderr 专用于运维诊断日志。
• Destroy、RPC 插件和 Cubelet Attach/Detach 保持原有错误处理机制。

private_data 契约

约束说明
接口旧接口 POST /volumes 保持 name / driver 定义不变；新接口 POST /v2/volumes 接受可选 private_data 并原样转发给 CubeMaster POST /cube/volume。
内容约束调用方输入 A 与插件 Create 返回状态 B 均须为有效 UTF-8、长度 ≤ 1024 字节（按字节而非字符计算）、不含 NUL 字节且仅含 BMP 字符（≤ U+FFFF）。CubeMaster 视为不透明字符串，不解析 JSON、不 trim 空白；校验失败返回 HTTP 400（ret_code = 130400）。
状态流转Create 接收 A 并可返回规范化后的状态 B；CubeMaster 只持久化 B 并转发给 Attach 与 Destroy。若插件返回空字符串，就存空值，不会回退到 A。
创建回滚若 Create 成功但 B 校验或 DB 更新失败，CubeMaster 会尽力调用 Destroy(volumeID, B) 清理后端资源（回滚失败只记录 volume_id、driver、phase 与固定错误类别，不记录原始状态）。
安全红线private_data 明文存储在数据库并经注解 / CLI 参数透传，只允许放桶名、前缀、地域或凭证引用（如 cred_ref），严禁放明文密钥。插件不得将 private_data 打印到日志或拼进错误信息。

第 2 步：编写插件代码（main.go）

package main

import (
    "encoding/json"
    "flag"
    "fmt"
    "os"
    "os/exec"
    "path/filepath"
    "regexp"
    "strings"
)

var validVolumeID = regexp.MustCompile(`^[a-zA-Z0-9_-]{1,128}$`)

type createResp struct {
    Token       string `json:"token"`
    PrivateData string `json:"private_data"`
    Error       string `json:"error"`
    ErrorKind   string `json:"error_kind,omitempty"` // 成功时必须省略
}

type attachResp struct {
    HostPath string            `json:"host_path"`
    Metadata map[string]string `json:"metadata,omitempty"`
    Error    string            `json:"error"`
}

type basicResp struct {
    Error string `json:"error"`
}

func storageRoot() string {
    if v := strings.TrimSpace(os.Getenv("CUBE_DEMO_STORAGE_ROOT")); v != "" {
        return filepath.Clean(v)
    }
    return "/var/lib/cube-demo-volumes"
}

// resolveUnderRoot 确保路径严格落在 root 之内，防止路径穿越。
func resolveUnderRoot(root, candidate string) (string, error) {
    cleanRoot := filepath.Clean(root)
    cleanPath := filepath.Clean(candidate)
    rel, err := filepath.Rel(cleanRoot, cleanPath)
    if err != nil || rel == "." || rel == ".." || strings.HasPrefix(rel, ".."+string(os.PathSeparator)) {
        return "", fmt.Errorf("path is outside allowed root")
    }
    return cleanPath, nil
}

func writeJSON(v any) {
    _ = json.NewEncoder(os.Stdout).Encode(v)
}

func failBasic(msg string) {
    writeJSON(basicResp{Error: msg})
    os.Exit(1)
}

func failCreate(msg, kind string) {
    writeJSON(createResp{Error: msg, ErrorKind: kind})
    os.Exit(1)
}

func isMountPoint(path string) bool {
    return exec.Command("mountpoint", "-q", path).Run() == nil
}

func handleCreate(volumeID string) {
    if !validVolumeID.MatchString(volumeID) {
        failCreate("volume_id has an invalid format", "invalid_argument")
    }

    root := storageRoot()
    backingDir, err := resolveUnderRoot(root, filepath.Join(root, volumeID))
    if err != nil {
        failCreate("invalid volume_id", "invalid_argument")
    }
    if err := os.MkdirAll(backingDir, 0755); err != nil {
        fmt.Fprintf(os.Stderr, "mkdir %s: %v\n", backingDir, err)
        failCreate("failed to provision backend directory", "")
    }

    // 将解析好的后端路径作为 private_data 返回，CubeMaster 会落库并透传给 Attach / Destroy
    writeJSON(createResp{
        Token:       "",
        PrivateData: backingDir,
        Error:       "",
    })
}

func handleDestroy(volumeID, privateData string) {
    if !validVolumeID.MatchString(volumeID) {
        failBasic("invalid volume_id")
    }

    root := storageRoot()
    candidate := privateData
    if candidate == "" {
        candidate = filepath.Join(root, volumeID)
    }
    backingDir, err := resolveUnderRoot(root, candidate)
    if err != nil {
        failBasic("invalid backing path")
    }
    if err := os.RemoveAll(backingDir); err != nil {
        fmt.Fprintf(os.Stderr, "remove %s: %v\n", backingDir, err)
        failBasic("failed to remove backend directory")
    }
    writeJSON(basicResp{Error: ""})
}

func handleAttach(volumeID, volumeBaseDir, privateData string, refCount int64) {
    if !validVolumeID.MatchString(volumeID) {
        failBasic("invalid volume_id")
    }
    if volumeBaseDir == "" || !filepath.IsAbs(volumeBaseDir) {
        failBasic("volume-base-dir must be an absolute path")
    }

    // hostPath 必须严格位于 volumeBaseDir 内
    mountDir, err := resolveUnderRoot(volumeBaseDir, filepath.Join(volumeBaseDir, "demo-"+volumeID))
    if err != nil {
        failBasic("invalid mount_dir")
    }

    // 仅在本节点首次挂载（refCount == 0）时建立后端挂载；refCount > 0 直接复用
    if refCount == 0 {
        root := storageRoot()
        candidate := privateData
        if candidate == "" {
            candidate = filepath.Join(root, volumeID)
        }
        backingDir, err := resolveUnderRoot(root, candidate)
        if err != nil {
            failBasic("invalid backing path")
        }
        if _, err := os.Stat(backingDir); err != nil {
            fmt.Fprintf(os.Stderr, "stat %s: %v\n", backingDir, err)
            failBasic("backing storage does not exist")
        }
        if err := os.MkdirAll(mountDir, 0755); err != nil {
            fmt.Fprintf(os.Stderr, "mkdir %s: %v\n", mountDir, err)
            failBasic("failed to prepare mount directory")
        }
        if !isMountPoint(mountDir) {
            if out, err := exec.Command("mount", "--bind", backingDir, mountDir).CombinedOutput(); err != nil {
                fmt.Fprintf(os.Stderr, "mount --bind %s %s: %v (%s)\n", backingDir, mountDir, err, strings.TrimSpace(string(out)))
                failBasic("failed to mount volume")
            }
        }
    }

    writeJSON(attachResp{
        HostPath: mountDir,
        Metadata: map[string]string{"mount_dir": mountDir},
        Error:    "",
    })
}

func handleDetach(metadataRaw string, refCount int64) {
    // 本节点仍有其他沙箱挂载时不做卸载（no-op）
    if refCount > 0 {
        writeJSON(basicResp{Error: ""})
        return
    }

    var meta map[string]string
    if metadataRaw != "" {
        if err := json.Unmarshal([]byte(metadataRaw), &meta); err != nil {
            fmt.Fprintf(os.Stderr, "parse metadata: %v\n", err)
            failBasic("invalid metadata json")
        }
    }

    mountDir := meta["mount_dir"]
    if mountDir != "" && isMountPoint(mountDir) {
        if out, err := exec.Command("umount", mountDir).CombinedOutput(); err != nil {
            fmt.Fprintf(os.Stderr, "umount %s: %v (%s)\n", mountDir, err, strings.TrimSpace(string(out)))
            failBasic("failed to unmount volume")
        }
        // 仅移除空挂载点，保留 backingDir 中的持久数据
        _ = os.Remove(mountDir)
    }
    writeJSON(basicResp{Error: ""})
}

func main() {
    op := flag.String("op", "", "hook operation: create | destroy | attach | detach")
    volumeID := flag.String("volume-id", "", "stable volume identifier")
    _ = flag.String("name", "", "human-readable volume name")
    _ = flag.String("sandbox-id", "", "sandbox identifier")
    _ = flag.String("namespace", "", "containerd namespace")
    refCount := flag.Int64("ref-count", 0, "pre-attach or post-detach ref count")
    volumeBaseDir := flag.String("volume-base-dir", "", "required parent directory for host_path")
    privateData := flag.String("private-data", "", "opaque plugin state")
    metadata := flag.String("metadata", "", "JSON metadata echoed back on detach")
    flag.Parse()

    switch *op {
    case "create":
        handleCreate(*volumeID)
    case "destroy":
        handleDestroy(*volumeID, *privateData)
    case "attach":
        handleAttach(*volumeID, *volumeBaseDir, *privateData, *refCount)
    case "detach":
        handleDetach(*metadata, *refCount)
    default:
        failBasic(fmt.Sprintf("unsupported op: %q", *op))
    }
}

10何时用 RPC 与开发运维规范

10.1 什么时候选择开发 RPC 插件

如果插件需要维持后端连接池、内存缓存或避免高频 fork 开销，可以将协议切换为 type: rpc：

  1. 导入 github.com/tencentcloud/CubeSandbox/pkgs/proto/services/volumeplugin/v1，分别实现 VolumeControllerServiceServer（Create / Destroy）和 VolumePluginServiceServer（Attach / Detach）。
  2. 监听 Unix socket（如 /run/my-plugin.sock）或 TCP 端口，并在 CubeMaster / Cubelet 中配置 type: rpc 与 socket_path。
  3. Node 侧需确保挂载进入 Cubelet 的 mount namespace。
判断条件选 binary选 rpc
调用频率常规（沙箱创建 / 销毁时）超高频、低延迟
是否需要长连接池 / 内存缓存不需要需要复用
运维成本低（免守护进程）需托管常驻进程

11易错点

易错点 1：把只读当成卷的全局属性。读写 / 只读是每次挂载的属性。同一个 Volume 可以同时以 rw 挂给写入沙箱、以 ro 挂给多个读取沙箱。只读不是不可变快照，读写沙箱的写入仍然可见。
易错点 2：Detach 时删除后端数据。Node Detach 只负责卸载宿主机侧挂载（FUSE / NFS / bind），绝不能删除后端持久数据；真正的删除只发生在 Controller Destroy。
易错点 3：忘记 refCount 语义方向。Attach 收到的是「挂载前」计数，Detach 收到的是「卸载后」计数。写反会在 refCount > 0 时误卸载共享挂载，导致其他沙箱 I/O 报错。
易错点 4：binary 插件往 stdout 打日志。stdout 只能输出唯一合法 JSON；任何日志、子命令输出都必须重定向到 stderr，否则会出现 decode stdout: invalid character ...。
易错点 5：用宿主根 mntns 排查挂载。Cubelet 运行在独立 mount namespace 中，宿主机 mount / /proc/mounts 看不到插件挂载。请用 nsenter -t "$CPID" -m 进入 Cubelet mntns 检查。
易错点 6：在 private_data 里放明文密钥。private_data 明文存库并经注解 / CLI 透传，只允许放桶名、前缀、地域或 cred_ref 这类凭证引用名，严禁放 AccessKey / SecretKey。
易错点 7：删除前没先杀沙箱。只要 t_cube_volume.refcount ≠ 0，DELETE /volumes/:id 就返回 409。必须先销毁所有挂载该卷的沙箱（Detach），再 Volume.destroy。
易错点 8：多驱动集群省略 driver。省略 driver 时使用 volume_plugins 列表第一项。多后端集群应在代码里显式传 driver，避免落到非预期插件。

12记忆卡片

双角色Controller（CubeMaster）管 Create / Destroy；Node（Cubelet）管 Attach / Detach。
RefCount 方向Attach 传「挂载前」计数，Detach 传「卸载后」计数；0 才真正 mount / umount。
两级计数节点本地决定是否真正挂载；集群级 t_cube_volume.refcount 决定能否删除（≠0 → 409）。
挂载链hostPath → per-sandbox bind → virtiofs → MicroVM；只读由 Cubelet 重挂，插件不关心。
binary vs rpcbinary 每次 fork、自动继承 Cubelet mntns；rpc 常驻、需自行对齐 mntns。
stdout 纪律binary 的 stdout 只输出一行 JSON；日志一律进 stderr。
private_data≤1024 字节、只存 B 不回退 A、只放引用名不放密钥。
快照语义external-reference：快照只存卷 ID + 路径 + 只读标志，不复制数据。

13自测题

自测

1. 同一节点上有 3 个沙箱依次挂载同一个 Volume，再依次销毁。请描述 Cubelet 传给插件的 refCount 序列，以及何时真正 mount / umount。

Attach 依次收到 0（首次 mount）、1、2（复用 hostPath）；Detach 依次收到 2、1、0。只有第一个 Attach（refCount=0）真正建立后端挂载，只有最后一个 Detach（refCount=0）真正 umount，且 umount 只拆宿主机侧挂载、保留后端数据。

2. 为什么 Cubelet 要在独立 mount namespace 中运行？这对 binary 与 rpc 插件分别意味着什么？

这样插件建立的 FUSE / NFS / bind 挂载只对 Cubelet 可见，宿主机根 mntns 的 /proc/mounts 看不到。binary 插件由 Cubelet fork/exec，自动继承 Cubelet mntns，无需额外处理；rpc 插件是独立常驻进程，运行在自己的 mntns 中，必须自行确保挂载进入 Cubelet 的 mntns（共享挂载传播或 nsenter），否则宿主机挂载成功但沙箱内是空目录。

3. 一个 binary 插件在 Create 时发现 cred_ref 缺失，应该怎样返回错误？如果成功呢？

失败时输出形如 {"error":"cred_ref is required","error_kind":"invalid_argument"} 的 JSON 并保持非零退出码（如 exit 1），CubeMaster 映射为 ret_code=130400、HTTP 400。成功时输出 {"token":"","private_data":"...","error":""}，并且必须省略 error_kind（Go 用 omitempty）；若成功响应带了非空 error_kind 或 error_kind 非空而 error 为空，都会被判为协议失败。
