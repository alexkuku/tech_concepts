1部署方式选择决策树

CubeSandbox 的所有沙箱都运行在 Micro-VM 里，因此部署的第一性问题只有一个：宿主机能不能提供 KVM。围绕这个判断，再加上「是否改源码」「是否多机」两个变量，就能唯一确定该走哪条路径。

场景 A

没有 /dev/kvm → 选 PVM

普通云服务器屏蔽了嵌套虚拟化。安装 PVM 宿主机内核并传入 CUBE_PVM_ENABLE=1，由 PVM 提供 KVM 能力。

场景 B

有 KVM 的物理机 → 裸金属

物理机、裸金属或已开启嵌套虚拟化的云服务器，/dev/kvm 可读写，一条在线安装命令即可。

场景 C

要改源码 / 定制 → 本地构建

需要自定义组件或扩展计算节点时，从源码构建发布包，再部署到目标机。适用于评估、开发测试。

场景 D

多节点生产 → 多机集群

先部署控制节点，再用 install-compute.sh 添加计算节点，横向扩容沙箱算力。

① 看虚拟化：执行 ls -la /dev/kvm，确认宿主机能否直接提供 KVM 设备。
↓
② 无 /dev/kvm（云服务器屏蔽嵌套虚拟化）→ 走 PVM 部署：装 PVM 内核后由 PVM 提供 KVM。
↓
③ 有 KVM（物理机 / 裸金属 / 已开嵌套虚拟化）→ 裸金属一键部署 即可。
↓
④ 需要改源码或定制组件 → 从源码构建发布包，走 本地构建部署。
↓
⑤ 需要横向扩容 / 生产多机 → 先起控制节点，再用 install-compute.sh 加计算节点，走 多机集群部署。
三种基础方式可以叠加。PVM 只是「让普通云主机具备 KVM 能力」，一旦 /dev/kvm 可用，后续安装、模板、SDK 流程与标准部署完全一致；多机集群的控制节点也可以是 PVM 或裸金属节点。因此决策树是「先定 KVM，再定规模」。
生产环境先做网络加固。四个官方页面都强调：在把服务暴露到不可信网络之前，请先阅读「网络加固」指南完成安全加固。

3PVM 部署：在普通云服务器上获得 KVM

PVM 部署相比标准部署只多两步：① 安装 PVM 宿主机内核并重启；② 安装时传入 CUBE_PVM_ENABLE=1。其余流程与快速开始完全一致。

3.1 原理：PVM 内核 + KVM 模块

PVM（Pagetable-based Virtual Machine）是一种基于页表的嵌套虚拟化框架，构建于 KVM 之上。与传统嵌套虚拟化不同，PVM 不依赖宿主 hypervisor 向 guest 暴露 Intel VT-x / AMD-V 等硬件虚拟化扩展，而是在 guest 内核层通过共享内存区域和影子页表（shadow page table）完成特权级切换与内存虚拟化，对宿主 hypervisor 完全透明。腾讯云已在生产环境大规模部署 PVM，并将改进成果开源至 OpenCloudOS 内核。

应用层
Cube Sandbox 组件Micro-VM 沙箱
Guest 内核
vmlinux-pvm（覆盖为运行时 vmlinux）
PVM 提供
kvm_pvm 模块/dev/kvm影子页表 + 共享内存
底层
PVM 宿主机内核普通云服务器（无 VT-x/AMD-V）

3.2 启动链路

Step 0：准备 x86_64 云服务器（推荐 OpenCloudOS 9；Ubuntu / Debian / CentOS 亦可）。
↓
Step 1：下载并安装 kernel-release-* 中的 PVM 宿主机内核包（RPM 或 DEB）。
↓
Step 2：设置 PVM 内核为默认启动项，并执行 host_grub_config.sh 配置内核启动参数。
↓
Step 3：reboot，用 uname -r 确认版本含 opencloudos9.cubesandbox.pvm.host。
↓
Step 4：modprobe kvm_pvm 加载模块 → /dev/kvm 出现。
↓
Step 5：以 CUBE_PVM_ENABLE=1 安装，安装脚本用 PVM guest 内核覆盖 vmlinux。

3.3 前置条件

  • x86_64 架构的 Linux 服务器（云服务器或物理机均可）
  • 有 root 权限（全文命令均在 root shell 执行，先 sudo su root）
  • 无需 /dev/kvm（安装 PVM 内核后由 PVM 提供 KVM 能力）
  • 内存 ≥ 8 GB、XFS 或可用于 /data/cubelet 的分区（与快速开始一致）
  • 规格建议：CPU ≥ 4 核、内存 ≥ 8 GB、系统盘 ≥ 50 GB（推荐挂额外数据盘给 /data/cubelet）

3.4 第一步：安装 PVM 宿主机内核

到 Releases 页面（过滤 kernel-release）下载内核主包：RPM 系为 kernel-*opencloudos9.cubesandbox.pvm.host*.x86_64.rpm，DEB 系为 linux-image-*opencloudos9.cubesandbox.pvm.host*_amd64.deb。kernel-headers-*、-dbg 为可选包，无需下载。

步骤RPM 系（OpenCloudOS / RHEL / CentOS / TencentOS / Fedora）DEB 系（Ubuntu / Debian）
安装内核包rpm -ivh --oldpackage kernel-*.rpmdpkg -i linux-image-*opencloudos9.cubesandbox.pvm.host*.deb
设默认启动项grubby --set-default-index=<index>改写 /etc/default/grub 的 GRUB_DEFAULT
配置启动参数host_grub_config.sh（DEB 内部会调用 update-grub）
重启reboot

RPM 系完整命令

# 若宿主机已有更高版本内核，--oldpackage 跳过版本号比较
rpm -ivh --oldpackage kernel-*.rpm

# 查看已安装内核列表，找到 PVM 内核对应的序号
grubby --info=ALL | grep -E "^kernel|^index"

# 将 <index> 替换为上面输出中 PVM 内核对应的数字
grubby --set-default-index=<index>

# 确认设置生效
grubby --default-kernel

# 配置内核启动参数
curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/pvm/grub/host_grub_config.sh | bash

DEB 系完整命令

dpkg -i linux-image-*opencloudos9.cubesandbox.pvm.host*.deb

# 查看已安装的内核列表，确认 PVM 内核版本字符串
ls /boot/vmlinuz-*

# 将 GRUB 默认启动项指向 PVM 内核（下面自动取实际版本字符串）
KVER="$(ls /boot/vmlinuz-*opencloudos9.cubesandbox.pvm.host* | sed 's|/boot/vmlinuz-||' | tail -1)"
sed -i "s|^GRUB_DEFAULT=.*|GRUB_DEFAULT=\"Advanced options for Ubuntu>Ubuntu, with Linux ${KVER}\"|" \
  /etc/default/grub

# 配置内核启动参数（脚本内部会调用 update-grub 使设置生效）
curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/pvm/grub/host_grub_config.sh | bash

reboot

3.6 第二步：安装 Cube Sandbox（启用 PVM）

发布包内含两份 guest 内核：普通版（vmlinux）和 PVM 版（vmlinux-pvm）。CUBE_PVM_ENABLE=1 告知安装脚本把 PVM guest 内核覆盖安装为运行时使用的 vmlinux；不设置则默认使用普通 guest 内核，PVM 不生效。

方式一：在线安装（推荐）——脚本下载到临时目录再执行，目录中无 .env，直接前置变量即可生效。

# 国内访问（推荐，从 CNB 拉取脚本）
curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/one-click/online-install.sh \
  | CUBE_PVM_ENABLE=1 MIRROR=cn bash

# 境外访问（从 GitHub 拉取脚本）
curl -sL https://github.com/tencentcloud/CubeSandbox/raw/master/deploy/one-click/online-install.sh \
  | CUBE_PVM_ENABLE=1 bash

# 多网卡机器可显式指定节点 IP
curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/one-click/online-install.sh \
  | CUBE_PVM_ENABLE=1 MIRROR=cn bash -s -- --node-ip=<你的服务器 IP>

方式二：手动下载发布包——解压后直接传入环境变量安装。

tar -xzf cube-sandbox-one-click-<sha>.tar.gz
cd cube-sandbox-one-click-<sha>

# 解压目录中不含 .env，环境变量可直接生效
CUBE_PVM_ENABLE=1 ./install.sh
env 文件覆盖陷阱。若你曾执行 cp env.example .env，目录中的 .env 默认 CUBE_PVM_ENABLE=0，安装脚本会 source 它并覆盖父 shell 传入的同名变量，导致 PVM 未启用。此时先改 .env： 
sed -i 's/^CUBE_PVM_ENABLE=0/CUBE_PVM_ENABLE=1/' .env
grep CUBE_PVM_ENABLE .env   # 期望：CUBE_PVM_ENABLE=1
./install.sh

3.7 第三步：验证 PVM 环境

# 确认运行时配置中 PVM 已启用
grep CUBE_PVM_ENABLE /usr/local/services/cubetoolbox/.one-click.env
# 期望：CUBE_PVM_ENABLE=1

# 确认 KVM 设备可用
ls -la /dev/kvm

# 确认 PVM KVM 模块已加载

环境就绪后，后续「制作模板 → 运行沙箱」与标准部署完全一致。

3.8 卸载

卸载会停止并删除服务、容器、数据卷、网络配置、运行数据和日志，已有模板、沙箱及快照数据也会被删除——执行前先备份。

sudo /usr/local/services/cubetoolbox/scripts/one-click/uninstall.sh
sudo /usr/local/services/cubetoolbox/scripts/one-click/uninstall.sh check
sudo rm -rf /usr/local/services/cubetoolbox
卸载脚本不会卸载 PVM 宿主机内核，也不会删除 Cube 相关 Docker 镜像；如需清理镜像请按脚本提示手动删除。

4裸金属 / 物理机部署

适用于已有支持 KVM 的 x86_64 或 aarch64（ARM64）Linux 机器，/dev/kvm 可用，例如物理机、裸金属服务器，或已开启嵌套虚拟化的云服务器。普通云服务器（/dev/kvm 不可用）请改用 PVM。

4.1 前置条件

  • x86_64 或 aarch64（ARM64）架构的 Linux 机器
  • /dev/kvm 存在且可读写（ls -la /dev/kvm）
  • 有 root 权限（sudo su root）
  • Docker 已安装并正常运行
  • 可访问互联网（下载发布包、拉取 Docker 镜像）
  • 内存 ≥ 8 GB，磁盘空余 ≥ 50 GB
一键装出来的组件：E2B 兼容 REST API 监听 3000 端口；CubeMaster、内置 network runtime 的 Cubelet、CubeShim 作为宿主机进程运行；MySQL 和 Redis 通过 Docker Compose 管理；CubeProxy 提供 TLS（mkcert）和 CoreDNS 域名路由（cube.app）。

4.2 第一步：安装

x86_64（AMD64）——以 root 身份执行

curl -sL https://cnb.cool/CubeSandbox/CubeSandbox/-/git/raw/master/deploy/one-click/online-install.sh | MIRROR=cn bash

ARM64（aarch64）——当前需手动下载发布包

online-install.sh 当前仅自动发现 x86_64 包，ARM64 自动检测与一键安装将后续补齐。目前请按以下手动步骤操作。
# 将 <version> 替换为你实际下载的版本（如 v0.5.0-rc3）
tar -xzf cube-sandbox-one-click-<version>-arm64.tar.gz
cd cube-sandbox-one-click-<version>-arm64
./install.sh
部分 aarch64 主机（较旧内核、嵌套虚拟化环境或某些 ARM 核心）KVM 不向 guest 暴露 PMUv3，此时 MicroVM 仍可正常启动，guest 只是看不到硬件性能计数器，无需额外操作。

4.3 第二步：制作模板

安装完成后，用预构建镜像创建代码解释器模板：

  --image cube-sandbox-cn.tencentcloudcr.com/cube-sandbox/sandbox-code:latest \
  --writable-layer-size 1G \
  --expose-port 49999 \
  --expose-port 49983 \
  --probe 49999

# 监控构建进度，等待状态变为 READY
cubemastercli tpl watch --job-id <job_id>
国内优先使用 cube-sandbox-cn.tencentcloudcr.com/cube-sandbox/sandbox-code:latest；境外访问推荐 cube-sandbox-int.tencentcloudcr.com/cube-sandbox/sandbox-code:latest。镜像较大，下载、解压、制作可能较久，请耐心等待。记录输出中的 template_id。

4.4 第三步：运行第一段代码

yum install -y python3 python3-pip
pip config set global.index-url https://mirrors.ustc.edu.cn/pypi/simple

    print(result)

  "https://cnb.cool/CubeSandbox/CubeSandbox/-/releases/download/kernel-release-260812-1/vmlinux-amd64"

# 若目标主机以 PVM 方式部署，另需下载 PVM guest 内核

  "https://cnb.cool/CubeSandbox/CubeSandbox/-/releases/download/kernel-release-260812-1/vmlinux-pvm-amd64"
vmlinux 是通用名称：x86_64 上是原始 ELF vmlinux；aarch64 上应为 make arch/arm64/boot/Image 产出的 PE/COFF boot Image（发布资产 vmlinux-arm64 即以此历史名发布）。原始 ELF vmlinux 无法在 aarch64 启动。可用仓库辅助目标生成正确镜像：make guest-kernel KERNEL_SRC=/path/to/linux KERNEL_TARGET_ARCH=aarch64。

6多机集群部署

在单机部署基础上通过「添加计算节点」扩展为多机集群。计算节点只运行沙箱运行时组件（内置 network runtime 的 Cubelet、CubeShim），向控制面注册。前置条件：必须先按「本地构建部署」完成控制节点部署。

6.1 组件拓扑

控制节点（完整技术栈 + 自身也是计算节点）
CubeMaster编排调度
CubeOps节点管理 :3010
cube-apiAPI 网关 :3000
CubeProxyTLS + CoreDNS
MySQL
Redis
MinIO S3:9000
Cubeletnetwork runtime
↓ /internal/v1/node-agent 注册与心跳（3010）
计算节点 #1Cubelet + CubeShim
计算节点 #2Cubelet + CubeShim
计算节点 #N

控制节点

运行完整技术栈：编排调度（CubeMaster）、节点管理（CubeOps）、API 网关（cube-api）、代理（CubeProxy + CoreDNS）、数据库（MySQL + Redis）、内置 MinIO S3 存储（供 volume 使用），同时自身也作为计算节点。

计算节点

只运行内置 network runtime 的 Cubelet，向控制面 CubeOps 注册并接收来自 CubeMaster 的沙箱调度请求。

6.2 前置条件

  • 每台计算节点需满足与控制节点相同的硬件/软件要求：物理机或裸金属（不支持嵌套虚拟化）、x86_64 或 aarch64、已启用 KVM（ls /dev/kvm）、Docker 已安装并运行
  • 所有集群节点（控制节点 + 全部计算节点）均已启用时间同步（chrony、ntpd、systemd-timesyncd、PTP 等）
  • 到控制节点的网络连通：默认需访问 CubeOps 的 3010 端口；使用内置 MinIO 时还需访问 9000 端口
务必要时间同步。若计算节点时间落后于控制节点，其心跳可能看起来已超过 15 秒过期窗口，导致节点被标记为不健康、模板也不会下发。时间恢复同步后 CubeMaster 通常会自动补齐缺失副本；如需立即触发可执行 template redo。

6.3 第一步：准备发布包

使用与控制节点相同的发布包，拷贝到计算节点并解压：

tar -xzf cube-sandbox-one-click-<version>.tar.gz
cd cube-sandbox-one-click-<version>

6.7 配置 CubeMaster 调度评分

多机部署时应在控制节点 cubemaster.yaml 的 scheduler 段设置评分（保留已有 filter、超时等配置）。未配置评分时，新沙箱可能集中到第一个可用节点，直到资源过滤器把流量推走。

scheduler:
  # 保留当前部署已有的 filter、超时和其他 scheduler 配置。
  priority_select_num: 3
  score:
    enable_scorers:
      - real_time_weighted_average
    resource_weights:
      mvm_num: 2
      local_create_num: 3
      quota_cpu_usage: 1
      quota_mem_usage: 1
    plugin_conf:
      real_time_weighted_average:
        weight: 1.0
        enable_weight_factors:
          - mvm_num
          - local_create_num
          - quota_cpu_usage
          - quota_mem_usage
默认配置 priority_select_num: 1 只决定「下一个沙箱落到哪个节点」，不会在多个高分节点间分散；小规模集群可从 3 起步并按节点数调整。scheduler.least_select_name 默认 random，通常无需显式设置。更新后按当前部署方式重启 CubeMaster 生效。

6.8 从客户端连接集群（4 种方式）

客户端需要 CubeAPI 控制面地址，以及一条通过 CubeProxy 访问沙箱的数据面链路。按客户端类型选择最简方式：

方式适用场景泛域名 DNS额外组件
CubeSandbox SDK 直连 + CUBE_PROXY_NODE_IPPython、Go、Node.js SDK不需要不需要
CubeProxy 路径模式curl、后端服务、通用 HTTP 客户端不需要不需要
E2B header 模式固定地址下使用官方 E2B SDK不需要不需要
泛域名 DNS（无 DNS 时用 E2B 开发 sidecar）生产环境、浏览器、SPA、官方 E2B SDK需要sidecar 需要

方式一：CubeSandbox SDK 直连 CubeProxy——保留虚拟 Host 做路由，无需泛域名 DNS。

export CUBE_API_URL="http://<控制面IP>:3000"
export CUBE_PROXY_NODE_IP="<CubeProxy节点IP>"
export CUBE_PROXY_PORT_HTTP=80
export CUBE_TEMPLATE_ID="<模板ID或别名>"

方式二：通用 HTTP 客户端 —— 路径模式——不需要 DNS 或证书，支持 WebSocket 升级；但不适合用根绝对路径（如 /static/app.js）加载资源的 SPA。

# 格式：http://<CubeProxy地址>:<HTTP端口>/sandbox/<sandbox-id>/<容器端口>/<路径>
curl http://10.0.0.5/sandbox/abc123/49999/health

方式三：固定地址下的官方 E2B SDK —— header 模式——Host 不带 <port>-<sandbox-id>.<domain> 路由属性时，CubeProxy 回退到 E2b-Sandbox-Id（必填）和 E2b-Sandbox-Port（可选，默认 envd 端口 49983）。

export E2B_API_URL="http://<cubeapi地址>:<api端口>"
export E2B_SANDBOX_URL="http://<cubeproxy地址>:<http端口>"
export E2B_API_KEY="<your-api-key>"
路径模式与 header 模式都在明文端口把整条数据面暴露给能访问 CubeProxy 的请求方，请仅在可信网络中使用。Host 路由保持优先，存量泛域名流量不受影响。

方式四：生产 / 浏览器 —— 泛域名 DNS——使用 <端口>-<sandbox-id>.<域名> 格式，需要配置指向 CubeProxy 的泛域名 A 记录，并让 CubeAPI 使用相同基础域名。

# 泛域名 A 记录示例
*.cube.example.com  →  <CubeProxy公网或内网IP>

export CUBE_API_SANDBOX_DOMAIN=cube.example.com
内置 CoreDNS 仅供本机解析 *.cube.app，主要用于本地体验；生产环境和多机共享环境应使用托管 DNS 或内网 DNS。/etc/hosts 不支持泛域名记录。没有 DNS 但必须用官方 E2B SDK 时，可用 E2B 开发 sidecar：配置 CUBE_REMOTE_PROXY_BASE="https://<CubeProxy节点IP>:443" 后 python demo.py，该地址必须指向 CubeProxy 而非 sidecar 自身监听地址。

8易错点、记忆卡片与自测

8.1 易错点 / 最佳实践

① .env 覆盖 CUBE_PVM_ENABLE。先 cp env.example .env 再 CUBE_PVM_ENABLE=1 ./install.sh 会被 .env 里的 0 覆盖，务必先 sed 改 .env 或用在线安装脚本。
② 时间不同步 = 假死节点。计算节点时钟落后会让心跳看起来超过 15 秒过期窗口，节点被判不健康、模板也不下发。全集群统一时间同步。
③ CUBE_S3_* 缺失只是告警。不配也能装，但 S3 卷插件不可用；从控制节点 grep '^CUBE_S3_' .one-click.env 回填后重装即可。
④ 网段冲突会直接中止安装。CUBE_SANDBOX_NETWORK_CIDR 与宿主机网卡/路由/DNS 冲突时前置检测中止；确需跳过用 ..._SKIP_CONFLICT_CHECK=1（不推荐）。
⑤ 卸载有保留项。卸载脚本不删 PVM 宿主机内核、也不删 Cube 的 Docker 镜像；集群需控制节点与计算节点分别卸载。
⑥ 多机默认只打分不分散。priority_select_num 默认 1，只在单个节点上决策；多机集群建议设为 3 并随规模调整。

8.2 记忆卡片

一句话没有 /dev/kvm 选 PVM，有 KVM 选裸金属，改源码选本地构建，要扩容选多机。
PVM 两个动作装 PVM 宿主机内核 + 重启；安装时传 CUBE_PVM_ENABLE=1。
PVM 验证三连uname -r 含 pvm.host → modprobe kvm_pvm → ls -la /dev/kvm。
构建三产物发布包 tar.gz、Guest 镜像 cube-guest-image-cpu.img、内核包 cube-kernel-scf.zip。
集群两角色控制节点跑全套 + 自身也算计算节点；计算节点只跑 Cubelet + CubeShim，向 3010 注册。
四接入方式SDK 直连、路径模式、header 模式、泛域名 DNS（无 DNS 用 sidecar）。

8.3 自测

自测（点击展开答案）

Q1：一台普通云服务器上 ls -la /dev/kvm 报「No such file or directory」，应该走哪种部署？关键开关是什么？

走 PVM 部署。先安装 PVM 宿主机内核（RPM 或 DEB）并 reboot 进入含 opencloudos9.cubesandbox.pvm.host 的内核，modprobe kvm_pvm 后由 PVM 提供 /dev/kvm；安装时必须传入 CUBE_PVM_ENABLE=1，否则会用普通 guest 内核导致 PVM 不生效。注意 .env 里的 CUBE_PVM_ENABLE=0 会覆盖该变量。

Q2：多机集群里，计算节点需要配置哪些关键变量？为什么 smoke.sh 通过但控制面看不到节点？

关键变量：ONE_CLICK_DEPLOY_ROLE=compute、CUBE_SANDBOX_NODE_IP=<当前节点IP>、ONE_CLICK_CONTROL_PLANE_IP=<控制节点IP>（或 ..._CUBEOPS_ADDR 显式指定 :3010），以及强烈建议的 CUBE_S3_*。看不到节点时：看 /data/log/Cubelet/、确认 meta_server_endpoint 指向正确 CubeOps、确保 CUBE_SANDBOX_NODE_IP 是可路由 IP（不是 127.0.0.1），并检查控制节点 3010 防火墙与时间同步。

Q3：客户端要访问集群里的沙箱，四种方式分别适合什么场景？各是否需要泛域名 DNS？

① CubeSandbox SDK 直连 + CUBE_PROXY_NODE_IP：Python/Go/Node.js SDK，无需 DNS；② 路径模式 /sandbox/<id>/<port>/<path>：curl、后端服务、通用 HTTP 客户端，无需 DNS，支持 WebSocket 但不适合根绝对路径的 SPA；③ header 模式 E2b-Sandbox-Id：固定地址下用官方 E2B SDK，无需 DNS；④ 泛域名 DNS <port>-<id>.<domain>：生产、浏览器、SPA，需要泛域名 A 记录（无 DNS 时用 E2B 开发 sidecar）。
