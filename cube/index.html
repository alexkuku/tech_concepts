部署没有 KVM 选 PVM；有 KVM 选裸金属；要改源码选本地构建；多节点生产选集群/K8s。
生命周期创建 → 运行 → 空闲自动暂停 → 有请求自动恢复 → 超时销毁。暂停可恢复，销毁不可逆。

自测：合上文档，试着回答

1. 为什么说 CubeSandbox 的快照比传统 VM 快？

关键在 CubeCoW 写时复制与增量脏页追踪：快照不需要完整复制磁盘/内存，只记录检查点与差异页，因此能做到百毫秒级；恢复时按需加载。传统 VM 快照往往要复制或冻结完整状态，秒到分钟级。

2. 一个沙箱从“创建”到“销毁”，中间可能经历哪些状态？

至少包含创建中、运行中、暂停（自动或显式）、恢复中、销毁/死亡等状态；具体状态名以第 05 章状态机为准。关键是区分“暂停可恢复”和“销毁不可逆”，以及 timeout 在恢复后如何重置。

3. 模板和快照都能“恢复出一个沙箱”，区别是什么？

模板是长期可复用的启动基线，通常由 OCI 镜像构建并分发到节点，适合发布环境；快照是某个沙箱在某一时刻的检查点，有有效期，适合保存现场、克隆分支或跨机迁移。

4. 出网策略和 CubeEgress 各自管什么？

出网策略在 L3/L4 决定哪些 IP/CIDR/端口可以出网，由 CubeVS 下发；CubeEgress 在 L7 做域名白名单、未授权出口阻断、凭据动态注入和审计，密钥不进入沙箱。

5. 排查“沙箱启动慢”时，应该先看哪三类信号？

先看请求指标（CubeProxy 的延迟/并发）、资源指标（host_sandbox / guest_workload 的 CPU/内存/统计周期）、日志（Cubelet、CubeShim/VMM、cube-proxy）。第 14、15 章给了对应的 PromQL 与日志路径。

学习提醒： 文档中的性能数字（41ms、92.4ms、121.9ms、512/s 等）来自特定裸金属环境的 CubeBench 实测，仅用于建立量级直觉；生产选型请以你所在环境的实测为准。
