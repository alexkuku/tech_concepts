3Python SDK

cubesandbox 是官方 Python SDK，提供符合 Python 使用习惯的接口，用于创建沙箱、执行代码与命令、管理文件以及控制沙箱完整生命周期。它是上手最快、与 Agent / 数据科学生态结合最自然的一套。

安装与环境要求

要求 Python 3.9 或更高版本，直接用 pip 安装：

pip install cubesandbox

配置

通过环境变量配置 CubeAPI 地址与模板 ID；如果部署环境无法解析 *.cube.app 泛域名，远程访问时还需要指定 CubeProxy 节点 IP。

# 必填：CubeAPI 地址与模板
export CUBE_API_URL=http://<your-cubeapi-host>:3000
export CUBE_TEMPLATE_ID=<your-template-id>

# 无法解析 *.cube.app 时，远程访问需要配置
export CUBE_PROXY_NODE_IP=<your-cubeproxy-node-ip>

也可以在代码中显式配置，避免依赖环境变量：

from cubesandbox import Config, Sandbox

config = Config(
    api_url="http://127.0.0.1:3000",
    template_id="<your-template-id>",
    proxy_node_ip="<your-cubeproxy-node-ip>",
)

with Sandbox.create(config=config) as sandbox:
    result = sandbox.run_code("1 + 1")
    print(result.text)

快速开始

下面这段完整代码演示「执行代码 → 执行命令 → 写文件 → 读文件」四件事。with 代码块退出时会自动销毁沙箱。

from cubesandbox import Sandbox

with Sandbox.create() as sandbox:
    code = sandbox.run_code('print("hello from CubeSandbox")')
    print(code.logs.stdout)

    command = sandbox.commands.run("uname -a")
    print(command.stdout)

    sandbox.files.write("/tmp/hello.txt", "Hello, world!")
    print(sandbox.files.read("/tmp/hello.txt"))

主要能力清单

  • 执行代码，支持变量持久化与流式输出。
  • 执行 Shell 命令和交互式 PTY 会话。
  • 读写、列出、监听、重命名和删除文件。
  • 暂停并重新连接沙箱，同时保留内存状态。
  • 创建快照、回滚和克隆沙箱。
  • 创建并挂载持久卷或宿主机目录。
  • 配置计算节点调度以及 L3/L4、L7 网络策略。
完整 API 参考与高级示例见 Python SDK 中文 README。

4Go SDK

CubeSandbox Go SDK 支持沙箱生命周期管理、代码执行、命令、PTY、文件操作、快照、克隆、回滚、持久卷和网络策略。它的配置项最完整，尤其适合需要精细控制 HTTP 传输和流式上传的后端服务。

安装

go get github.com/tencentcloud/CubeSandbox/sdk/go

配置

Go SDK 除了标准的 CUBE_API_URL、CUBE_TEMPLATE_ID，还提供完整的远程数据面访问配置：

export CUBE_API_URL=http://127.0.0.1:3000
export CUBE_TEMPLATE_ID=<your-template-id>

# 可选的远程数据面访问配置
export CUBE_PROXY_NODE_IP=<cubeproxy-node-ip>
export CUBE_PROXY_PORT_HTTP=80
export CUBE_PROXY_SCHEME=http
export CUBE_SANDBOX_DOMAIN=cube.app
NewConfigFromEnv 同时支持 E2B_API_URL 和 E2B_API_KEY；Cube 专用环境变量的优先级更高。这意味着从 E2B 迁移过来的配置可以平滑复用。

快速开始

package main

import (
    "context"
    "fmt"

    cubesandbox "github.com/tencentcloud/CubeSandbox/sdk/go"
)

func main() {
    ctx := context.Background()
    client := cubesandbox.NewClient(cubesandbox.NewConfigFromEnv())
    defer client.Close()

    sandbox, err := client.Create(ctx, cubesandbox.CreateOptions{})
    if err != nil {
        panic(err)
    }
    defer sandbox.Kill(ctx)

    result, err := sandbox.RunCode(ctx, "x = 41\nx + 1", cubesandbox.RunCodeOptions{})
    if err != nil {
        panic(err)
    }
    fmt.Println(result.Text)
}
易错：Client.Close 只释放本地空闲 HTTP 连接，不会销毁远程沙箱。清理沙箱用 Sandbox.Kill，想保留现场后续重连则用 Sandbox.Pause。

主要能力清单

  • 执行代码和 Shell 命令。
  • 创建、重连、调整和控制交互式 PTY。
  • 完整的文件系统操作、流式文件上传与下载，以及目录监听。
  • 创建快照、回滚以及并发克隆。
  • 管理持久卷和宿主机目录挂载。
  • 暂停并重新连接沙箱。
  • 配置节点调度、远程代理以及 L3/L4、L7 出网策略。

流式文件上传（重点）

Files.WriteFrom(ctx, path, src io.Reader) 从 reader 上传文件，无需先把整个文件读入内存。例如用 os.Open 打开本地产物后上传（需要导入 os）：

file, err := os.Open("artifact.tar.gz")
if err != nil {
    panic(err)
}
defer file.Close()

if err := sandbox.Files().WriteFrom(ctx, "/tmp/artifact.tar.gz", file); err != nil {
    panic(err)
}

这个方法同样支持 ForUser。它的行为契约比较特殊，接入前务必理解下面几点：

行为说明
reader 消费SDK 只消费一次 reader，不关闭它，不重试被拒绝的上传，也不跟随重定向。
实现方式使用一个按需读取的 goroutine、32 KiB 缓冲区和 multipart 边界。
服务端要求服务端及代理需支持未知长度请求体（HTTP/1.1 使用 chunked）。
兼容回退旧端点不支持 multipart 且可接受完整缓冲时，可改用 octet-stream 的 Write([]byte)；WriteFrom 不会重放 reader 做兼容。
自定义 transport报告 GotConn 和 WroteHeaders 的自定义 transport 必须报告 WroteRequest，缺少完成回调会返回错误。
超时用 context deadline 或注入 HTTP 客户端的 Timeout 限制整个操作，两者取较早值；都未设置时，成功响应后的完成阶段使用 Config.RequestTimeout（默认 30 秒）。
取消与资源调用返回后，阻塞的源仍可能占用一个读取 goroutine 及其缓冲区；取消无法中断任意源内部的 Read。
原子性上传不是原子操作，失败时目标文件可能已被截断或部分写入。
代理限制CubeProxy 默认缓冲请求，256 MiB 限制包含 multipart 边界，超限返回 HTTP 413。
错误响应最多读取 64 KiB 加一个检测字节，超长信息会标记截断，并丢弃末尾不完整的 UTF-8 字符。
完整传输契约与限制请参阅 Go SDK README；集成测试步骤也写在那里。

5Node.js SDK

@cubesandbox/sdk 是官方 Node.js 和 TypeScript SDK。它使用 Promise、camelCase 和 async/await，功能范围与 Python SDK 保持一致，适合 Node 服务端与全栈 TypeScript 项目。

安装与环境要求

要求 Node.js 18 或更高版本。该包同时提供 ESM、CommonJS 构建和 TypeScript 类型声明。

npm install @cubesandbox/sdk

配置

export CUBE_API_URL=http://<your-cubeapi-host>:3000
export CUBE_TEMPLATE_ID=<your-template-id>

# 无法解析 *.cube.app 时，远程访问需要配置
export CUBE_PROXY_NODE_IP=<your-cubeproxy-node-ip>

快速开始

用 try / finally 确保沙箱被清理，是 Node 里最直观的写法：

import { Sandbox } from "@cubesandbox/sdk";

const sandbox = await Sandbox.create();

try {
  const code = await sandbox.runCode('print("hello from CubeSandbox")');
  console.log(code.logs.stdout);

  const command = await sandbox.commands.run("uname -a");
  console.log(command.stdout);

  await sandbox.files.write("/tmp/hello.txt", "Hello, world!");
  console.log(await sandbox.files.read("/tmp/hello.txt"));
} finally {
  await sandbox.kill();
}

自动清理（TypeScript 5.2+）

使用 TypeScript 5.2 和 Node.js 20 或更高版本时，可以通过显式资源管理（await using）自动清理沙箱：

await using sandbox = await Sandbox.create();
const result = await sandbox.runCode("1 + 1");
console.log(result.text);

主要能力清单

  • 执行代码，支持变量持久化、流式输出和空闲超时。
  • 执行 Shell 命令和交互式 PTY 会话。
  • 完整的文件系统操作和目录监听。
  • 暂停、重连、创建快照、回滚和克隆沙箱。
  • 管理持久卷和宿主机目录挂载。
  • 配置节点调度以及 L3/L4、L7 网络策略。
  • 在 ESM 或 CommonJS 应用中使用完整类型 API。
完整 API 参考、超时语义和开发说明见 Node.js SDK README。

7如何选择 SDK

三套 SDK 的能力几乎等价，选型主要看「你的服务用什么语言写」「部署在什么网络环境」「是否需要流式上传或 Volume」。先看语言生态，再看部署约束。

按语言生态

Python 生态

数据科学、Agent 脚本、Notebook、需要快速验证时选 cubesandbox。上下文管理器自动销毁沙箱，代码最短。

按语言生态

Go 后端

高并发服务、需要精细控制 HTTP transport、或要上传未知长度大文件时选 Go SDK，WriteFrom 无需整文件入内存。

按语言生态

Node.js / TypeScript

Node 服务端或全栈 TS 应用选 @cubesandbox/sdk，功能与 Python 对齐，支持 ESM / CommonJS 与完整类型。

按部署环境

远程 / 跨网络

无法解析 *.cube.app 时，三套 SDK 都需设置 CUBE_PROXY_NODE_IP 走数据面直连；Go 还可细调 scheme 与端口。

按部署环境

从 E2B 迁移

按能力需求

流式上传 / Volume

需要流式上传的优先 Go；需要 Volume、快照、克隆、暂停重连的，三套 SDK 均支持，按语言习惯选即可。

一句话选型：脚本与 Agent 选 Python，高并发后端与流式上传选 Go，全栈 TypeScript 选 Node.js；无论哪套，远程环境都先确认 CUBE_API_URL 与 CUBE_PROXY_NODE_IP。

8易错点、记忆卡片与自测

接入中最常踩的坑集中在四类：版本、网络、鉴权、HTTPS 证书。下面先给速查表，再用记忆卡片固化，最后用 3 道自测题检验理解。

易错点速查

类别典型现象处理方式
版本Python < 3.9 或 Node < 18 安装/运行失败升级运行时；await using 需 TS 5.2 + Node 20+
网络无法解析 *.cube.app，数据面连不上设置 CUBE_PROXY_NODE_IP 走数据面直连
网络Go 流式上传返回 HTTP 413CubeProxy 有 256 MiB 上限（含 multipart 边界），拆分或改用对象存储
鉴权请求被拒 / 无权限配置 CUBE_API_KEY（Go 兼容 E2B_API_KEY），确认 CubeAPI 地址正确
HTTPS 证书自签证书校验失败 / TLS 握手错误使用受信证书，或为客户端配置 CA；具体以官方部署文档为准
Go 传输自定义 transport 缺少完成回调报错实现 WroteRequest，并响应取消
最隐蔽的坑：Go 的 Client.Close 不会销毁远程沙箱，只释放本地空闲连接。忘记 Sandbox.Kill 会持续占用沙箱配额；上传失败时目标文件可能已被截断，重试前需自行处理半写状态。

记忆卡片

调用链应用 → SDK → CubeAPI（鉴权）→ CubeProxy → 沙箱。
三件套环境变量CUBE_API_URL + CUBE_API_KEY + CUBE_TEMPLATE_ID。
DNS 兜底解析不到 *.cube.app 就设 CUBE_PROXY_NODE_IP。
版本门槛Python 3.9+、Node 18+、await using 需 TS 5.2 / Node 20+。
Go 流式上传WriteFrom 只读一次、不关闭、不重试、不跟随重定向；代理上限 256 MiB。
清理沙箱Client.Close 不断沙箱；用 Sandbox.Kill 或 Pause。

自测

自测：检验你掌握了多少

1. 远程环境无法解析 *.cube.app，SDK 调用沙箱一直失败，应该改哪个配置？为什么？

设置 CUBE_PROXY_NODE_IP 指向 CubeProxy 节点 IP。沙箱数据面默认走 *.cube.app 泛域名，DNS 解析不到时就要让 SDK 直接连数据面节点，绕过泛域名解析。

2. Go SDK 里调用 Client.Close() 之后，远程沙箱会被销毁吗？想保留现场后续重连该用什么？

不会。Client.Close 只释放本地空闲 HTTP 连接，不影响远程沙箱。销毁沙箱用 Sandbox.Kill；要保留内存状态、之后重连则用 Sandbox.Pause。

3. 用 Files.WriteFrom 上传大文件时，为什么可能收到 HTTP 413？SDK 会帮你重试吗？

CubeProxy 默认缓冲请求，限制为 256 MiB 且包含 multipart 边界，超限即返回 413。SDK 明确不重试被拒绝的上传、不重放 reader，需要调用方自行拆分或改用其他上传方式。
